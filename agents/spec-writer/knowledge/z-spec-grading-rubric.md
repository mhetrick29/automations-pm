# Z‑Spec One‑Page Checklist (v2.1.1)

> **How this file is used:** The spec-writer agent uses this rubric to (1) ensure all required elements are covered during brainstorm, (2) produce specs that score as high as possible, and (3) self-grade every generated spec before saving. The rubric was authored by VP-level leadership and is used by a grading agent to score specs. Note: the rubric does not distinguish between epic specs (time-bound, concrete) and full/vision specs — the themes apply to both, though some items (e.g., time-bound dates in SMART goals) are especially critical for epic specs.

---

## 1. Overview & Completeness

### Elevator Pitch
- [ ] Customer clearly identified
- [ ] Problem or goal clearly stated
- [ ] Customer outcome stated
- [ ] Business impact stated
- [ ] No implementation details
- [ ] Hypothesis present in this exact format:
  *If we do X for Y, then metric Z will move up by P, because data/research showed ABC*

### Customers / Users
- [ ] Explicit audiences defined
- [ ] No generic "users"
- [ ] Personas differentiated if needed

### Customer Problems & Insights
- [ ] Problems clearly articulated
- [ ] Value delivered stated
- [ ] Problems tagged (existing / latent / inferred)
- [ ] Supporting data or validation cited
- [ ] Confidence level in solving the problem stated

---

## 2. Goals

### Goals List
- [ ] Contains 2–7 goals
- [ ] "Why" is explained (not obvious/compliance)
- [ ] Each goal has a priority (P1 / P2 / P3)

### SMART Validation (per goal)
- [ ] Specific
- [ ] Measurable
- [ ] Achievable
- [ ] Relevant
- [ ] Time‑bound (explicit dates/quarters/milestones)

---

## 3. Features

For each feature:
- [ ] Written as a user capability
- [ ] High‑level (not tasks)
- [ ] Enough detail for high‑level costing
- [ ] Priority assigned (P1 / P2 / P3)

---

## 4. Success Metrics
- [ ] Business outcomes defined
- [ ] Customer outcomes defined
- [ ] Technical outcomes (if applicable)

For each metric:
- [ ] Key Result defined
- [ ] Priority assigned

---

## 5. Contributing Teams
- [ ] All collaborating teams listed
- [ ] High‑level ownership stated

---

## 6. Clarity & Correlation
- [ ] Spec logically structured and readable
- [ ] Goals clearly map to spec title
- [ ] Goals clearly link to org/team vision or stated parent objective

---

## 7. Start & End State
- [ ] Current state explicitly described
- [ ] Future state explicitly described
- [ ] Observable difference between states
